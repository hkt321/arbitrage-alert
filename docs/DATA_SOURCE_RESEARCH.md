# 本地行情数据源调研

调研日期：2026-05-31

## 结论

第一阶段建议优先做“多数据源融合”，不要把项目绑定到某一个行情软件。

推荐组合：

```text
实时行情/盘口：QMT 或 TdxQuant
基金申赎状态：基金公告、销售平台、基金公司公告
ETF PCF：交易所官方申购赎回清单
交易日历：交易所日历
费用参数：用户配置 + 基金公告 + 券商费率
```

原因：

- QMT / 通达信更擅长本地行情、K 线、分笔、盘口。
- 套利能否执行，还取决于申购限额、申赎状态、PCF、确认到账周期，这些通常不完全来自行情终端。
- 后续要加可转债、ETF、QDII、提醒渠道，必须保持数据源可替换。

## QMT / miniQMT

### 适合用途

- 本地实时行情。
- 全市场最新快照。
- 五档盘口。
- 历史行情下载。
- 股票、ETF、LOF、可转债等场内品种监控。
- 后续如果要自动交易，QMT 的交易接口更直接。

### 官方能力要点

迅投知识库把 QMT 行情分为三类：

- 本地数据：下载到本地的历史数据，适合回测。
- 全推数据：客户端启动后接收全市场最新快照，可用 `get_full_tick` 或 `subscribe_whole_quote`。
- 订阅数据：指定品种订阅分笔、1 分钟、5 分钟、日线等周期。

订阅存在数量上限，官方示例提到 300 个订阅量级，超出后可能返回前值，不是正确行情。

### 开通要求

通常路径：

1. 有支持 QMT / miniQMT 的券商账户。
2. 向券商申请 QMT 或 miniQMT 权限。
3. 获取软件下载链接。
4. 安装 QMT / miniQMT。
5. 安装 `xtquant`。
6. 登录客户端后，本地 Python 程序调用行情或交易接口。

开通要求不是全国统一标准，取决于券商。常见要求包括：

- 年满 18 岁，具备完全民事行为能力。
- 满足券商普通证券账户开通条件。
- 风险测评等级满足券商要求。
- 签署量化交易或程序化交易相关风险揭示。
- 部分券商要求交易经验或账户资产门槛。

非官方渠道常见说法是资产门槛约 10 万到 50 万不等，完整功能或极速柜台通常更高；这个必须以具体券商客户经理和官方流程确认为准。

### 费用

- QMT / miniQMT 软件权限很多情况下由券商提供，是否收费取决于券商。
- 股票、ETF、LOF 交易佣金按券商账户约定收取。
- Level-2 行情通常涉及交易所版权费用，可能单独收费。
- QMT 行情订阅数量超过基础限制时，可能需要购买行情 VIP 或增值服务。

### 风险与限制

- 必须本地或服务器持续登录客户端。
- Windows 环境最常见。
- 行情接口和交易接口依赖券商版本。
- 订阅数量、Level-2、极速柜台能力因券商而异。
- QMT 不一定提供完整的基金申购限额、基金公告和 ETF PCF 字段。

## 通达信 / TdxQuant

### 适合用途

- 本地行情看板。
- 实时与历史行情。
- 基金、ETF、LOF、REITs、可转债等数据。
- 指标、通达信公式和策略研发。
- 如果用户已经习惯通达信界面，接入体验较自然。
- 当前 QMT 暂时无法开通时，可以作为第一版行情源。

### 官方能力要点

TdxQuant 是通达信金融终端上的 Python 量化策略运行框架。官方说明：

- 需要预先启动支持 TQ 策略功能的通达信金融终端、专业研究、量化模拟版或期货通等版本。
- 支持 Python 3.7 到 3.14。
- 提供实时与历史快照、K 线、分笔数据。
- 提供股票、基金、指数、期货、宏观、可转债、期权等数据。
- 基金数据包含交易所上市基金的行情、净值等，包括 ETF、LOF、REITs。
- 指数数据包含沪深京指数、板块指数、港股指数、中证国证指数，并提供指数成分股能力。

### 开通要求

取决于具体通达信版本和服务：

- 普通行情客户端容易安装使用。
- TdxQuant 需要支持 TQ 策略功能的终端版本。
- 高级行情、Level-2、专业研究版、研究终端等通常需要订阅或授权。
- 第一版只做提醒，不接实盘交易，因此可以先用“金融终端量化模拟版”验证 TdxQuant 数据接口。
- 如果后续要实盘交易，仍需要确认券商交易接入、账号权限和交易函数是否可用。

### 费用

- 通达信有个人版、普及版、财富版、专业版、研究版、增值系列等不同产品入口。
- 是否收费、收费多少、是否含 Level-2，取决于版本和服务。
- 券商版通达信可能随券商账户提供基础行情。
- 官方 TdxQuant 文档没有给出统一开通价格；应以通达信官网、软件内购买页、客服或对应券商终端为准。

### 风险与限制

- 官方 TdxQuant 是较新的方向，项目接入时要验证接口稳定性和字段覆盖。
- 普通通达信客户端导出、本地文件、第三方 pytdx/opentdx 等路径，可能涉及协议稳定性和授权边界，不适合作为商业化或高可靠主数据源。
- 和 QMT 一样，申购限额、暂停申购、ETF PCF 等仍需要其他来源补充。
- 通达信能给行情、净值、指数和成分股，但不应假设它能完整给出基金申购限额、暂停申购公告和 ETF PCF。
- TdxQuant 脚本通常依赖客户端目录下的 `PYPlugins/user` 和 `tqcenter.py`，需要本地 Windows 客户端持续运行。

### 当前可执行方案

在 QMT 暂时无法开通的情况下，第一版改走：

```text
TdxQuant 行情/指数/基金净值
  + 交易所 ETF PCF
  + 基金公告/申购限额
  + 自定义费用配置
  + 估值误差回放
```

第一阶段验证目标：

1. 能否通过 TdxQuant 获取 ETF、LOF、可转债的实时快照。
2. 能否获取 5 档盘口或至少买一卖一。
3. 能否获取基金净值字段。
4. 能否获取指数行情和指数成分股。
5. 数据刷新频率是否满足 10 秒到 60 秒的提醒需求。
6. 客户端是否能长期稳定运行。

### 通达信客服/确认问题

通达信官网显示客服电话：027-87788668。

需要确认：

```text
1. 现在个人用户使用 TdxQuant 需要哪个终端版本？
2. 金融终端量化模拟版是否免费，是否需要注册登录？
3. 普通金融终端、专业研究版、量化模拟版的 TdxQuant 数据范围是否一致？
4. ETF、LOF、REITs、可转债是否支持实时快照、买一卖一、五档盘口、成交额？
5. 是否支持 Level-2 行情接口？如果支持，费用是多少？
6. 基金净值字段是否包含最新净值、估算净值、IOPV？
7. 是否能获取指数成分股和权重？
8. 是否能获取 ETF PCF 或申购赎回清单？
9. 是否能长期运行在本地电脑或云 Windows 主机？
10. 是否允许程序化调用数据用于个人提醒工具？
```

## 其他选择

### AkShare / 东方财富 / 新浪等公开数据

优点：

- 起步快。
- 适合原型验证。
- 不需要券商权限。

缺点：

- 接口不稳定。
- 可能限流。
- 数据口径不一定适合盘中套利。
- 盘口深度、申赎状态、公告时效未必足够。

适合做备用或校验源，不建议做唯一生产源。

### Wind / iFinD / Choice

优点：

- 数据完整。
- 公告、基金、财务、宏观覆盖强。
- 机构级稳定性更好。

缺点：

- 成本高。
- 个人使用门槛高。
- 本地自动化接入需要额外授权。

现阶段不建议作为 MVP 首选。

## PTrade

### 是什么

PTrade 通常指恒生电子体系的券商量化交易平台，由券商采购后提供给客户使用。它和 QMT 都属于券商量化工具，但运行模式不同：

```text
QMT / miniQMT：本地客户端登录，本地 Python 程序通过 xtquant 调行情和交易
PTrade：策略更多运行在券商侧平台，按事件驱动执行 Python 策略
```

公开资料显示，PTrade 面向私募机构和高净值投资者，提供量化投研、回测、模拟、实盘交易、算法工具等能力；券商上线情况、权限和门槛由具体券商决定。

### 适合用途

- 中低频自动化交易。
- 条件单、网格、篮子交易等券商内置工具。
- 策略托管在券商侧运行，减少个人电脑掉线影响。
- 后续如果做自动交易，PTrade 可以作为交易执行通道候选。

### 对本项目的价值

可以用，但更适合第二阶段以后：

- 第一阶段“套利提醒看板”需要大量外部数据融合：基金公告、申购限额、ETF PCF、海外节假日、费用、盘口。
- PTrade 的优势在交易执行和券商侧托管，不一定适合作为我们自己的数据融合中枢。
- 如果券商的 PTrade 允许外网访问或 HTTP 数据传入，它可以接收我们系统算出的信号，再负责下单或条件单。
- 如果券商的 PTrade 不允许外部联网，策略只能使用平台内置数据，可能会缺少 QDII 溢价、申购限额、公告、可转债强赎等外部因子。

### 开通要求和费用

没有统一标准，取决于券商：

- 是否支持 PTrade。
- 是否面向个人开放。
- 资产门槛是 10 万、30 万、50 万还是更高。
- 是否收软件费。
- 是否支持 Level-2。
- 是否允许策略访问外网。
- 是否支持 ETF、LOF、可转债、融资融券、期权等品种。

这些必须问券商客户经理或官方客服确认。

### 和 QMT 的取舍

| 维度 | QMT / miniQMT | PTrade |
| --- | --- | --- |
| 运行位置 | 本地电脑或云 Windows 主机 | 多数是券商侧策略环境 |
| 外部数据接入 | 本地程序更灵活 | 取决于券商是否开放外网/HTTP |
| 行情接入 | 适合本地行情采集 | 适合策略内使用平台行情 |
| 自动交易 | 支持，依赖券商权限 | 支持，偏托管式执行 |
| 做提醒看板 | 更方便 | 不一定方便 |
| 做无人值守交易 | 需要本地/云主机稳定运行 | 更有优势 |
| 数据融合 | 更适合作为数据中枢 | 更适合作为执行端 |

### 对我们的建议

第一版仍建议：

```text
本地服务做数据融合和提醒
QMT / miniQMT 或 TdxQuant 提供实时行情
官方公告/PCF 补充申赎限制
```

如果你能开 PTrade，可以把它列为后续交易执行模块：

```text
套利提醒系统 -> 生成信号 -> 人工确认 -> PTrade 条件单/策略执行
```

不建议第一版直接把 PTrade 作为核心架构，因为我们的关键难点是“发现真实可执行机会”，不是一开始就自动下单。

## 对本项目的建议

### 第一优先级

先设计统一接口：

```text
QuoteProvider        实时行情、盘口、成交额
FundMetaProvider     基金类型、申购状态、申购限额、赎回状态
PcfProvider          ETF 申购赎回清单
FeeProvider          佣金、申购费、赎回费、现金替代成本
CalendarProvider     A 股与海外市场交易日历
NoticeProvider       基金公告、大额申购公告
```

### MVP 数据源推荐

如果你能开 QMT：

```text
QMT 实时行情 + 交易所/基金公告补充申赎字段
```

如果暂时不能开 QMT：

```text
通达信/TdxQuant 或公开行情源 + 官方公告/PCF 补充字段
```

### 需要你向券商确认的问题

1. 是否支持 QMT / miniQMT。
2. 开通资产门槛是多少，是日均还是时点。
3. 是否要求交易经验、风险等级、风险揭示书。
4. 是否支持 Level-2。
5. Level-2 是否收费，按月还是按年。
6. 基础行情订阅上限是多少。
7. 是否支持 ETF、LOF、可转债的实时盘口。
8. 是否支持云服务器登录，是否限制异地登录。
9. 是否允许仅开行情权限，不开交易权限。
10. 佣金费率、ETF/LOF 佣金、最低收费是否可谈。

当前公开资料结论：

- 银河证券是券商账户来源，理论上应由银河决定能否开通 QMT / miniQMT。
- 公开搜索未确认到银河证券官网提供面向个人的 QMT / miniQMT 自助开通页面。
- 第三方资料提到银河证券可能支持 QMT，但开通门槛、软件费、Level-2、云服务器登录、miniQMT 权限必须以银河客户经理或官方客服确认为准。
- 银河证券官方客服电话：95551 或 4008-888-888。

需要向银河确认：

1. 我当前银河账户是否支持 QMT。
2. 是否支持 miniQMT，也就是能否在 QMT 登录界面看到“极简模式”或“独立交易”。
3. 是否可以只开行情权限，不开交易权限。
4. 开通资产门槛是多少，是时点资产还是 N 日日均资产。
5. 软件权限是否免费，免费条件是什么。
6. 是否支持 L1 五档全推行情。
7. 是否支持 Level-2 行情接口，费用是多少，是否能通过 miniQMT/xtquant 取到。
8. ETF、LOF、可转债是否有实时盘口、成交额、五档报价。
9. 可转债程序化交易或行情是否需要单独协议。
10. 是否允许云服务器登录 QMT / miniQMT，是否限制异地登录。
11. ETF/LOF 佣金费率和最低收费是多少，是否免五。
12. 是否支持 ETF 申赎业务、是否能在 QMT 内操作或查询。

### 同花顺

当前公开资料结论：

- 同花顺不是 QMT / miniQMT 的开通方，不能替代券商 QMT 权限。
- 普通同花顺适合人工看行情、资讯、Level-2 页面，不适合作为稳定自动化数据源。
- 同花顺 iFinD 数据接口支持 Python、HTTP 等方式，但产品主要面向专业用户或机构，成本和权限需要单独申请。
- iFinD 数据接口官方说明：SDK 接口同一时间只能一台设备登录；HTTP 接口支持绑定 IP；数据接口有 QPS 和数据量限制。
- 同花顺手机 Level-2 官方页面显示 288 元/年，提供上证 10 档、深证 500 档等展示能力；这更偏前端看盘，不等同于可供程序调用的 Level-2 数据接口。

适合本项目的用法：

- 同花顺普通版：作为人工核对行情和公告的辅助工具。
- 同花顺 Level-2：作为人工盘口观察工具，不作为第一版程序化数据源。
- iFinD：如果未来预算允许，可作为公告、基金元数据、日历、历史数据的专业数据源。

不建议：

- 用同花顺客户端抓屏或抓包作为核心行情源。
- 把同花顺 Level-2 会员等同于程序可调用的 Level-2 API。

## 第一批监控基金池说明

当前基金池优先覆盖容易出现场内溢价、但又经常受到申购额度或估值滞后影响的品种：

- 跨境 ETF：纳指、纳指 100、标普 500、中概互联网等，第一版优先使用 IOPV 或行情端参考净值。
- QDII-LOF：原油、油气、标普 500、纳指 100、标普信息科技、全球芯片、医疗/生物科技等。
- 商品 LOF：白银基金，第一版使用通达信候选期货合约中成交量最大的白银合约做代理估值。
- 境内 ETF 样本：沪深 300ETF，用于验证 PCF、IOPV 和低误差场景。

这些品种被加入“监控池”不等于一定可以套利。只有当申购/赎回状态、单日限额、成交额、盘口深度、费用、估值误差安全垫和模型置信度都过关时，看板才会给出“可执行”结论。海外指数和汇率实时源未接入前，相关 QDII-LOF 会被低置信度理由拦截或降级为观察。
