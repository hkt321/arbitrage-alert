# Eastmoney 小分页 LOF 行情加载器设计

## 目标

替换当前无法稳定完成的 `ak.fund_lof_spot_em()` 全量行情请求，同时保持个人提醒系统的轻量边界。AkShare 继续提供 `fund_purchase_em()` 的最新官方净值、净值日期、申购赎回状态、限额和费率；不新增第三方依赖。

## 方案

新增一个独立的 Eastmoney LOF 行情加载器，使用 Python 标准库直接请求公开的 `clist/get` 接口：

- 每页固定请求 20 条，仅请求代码、名称、价格、涨跌幅、成交量、成交额和换手率字段。
- 第一页读取总记录数，按总数逐页获取；每一页只请求一次，不使用备用域名或无限重试。
- 返回与 AkShare `fund_lof_spot_em()` 相同的必要列，使现有 `AkshareLofProvider` 只需替换默认行情 loader，合并与提醒逻辑保持不变。
- 请求显式直连，不继承当前进程的代理环境；不修改系统代理或永久环境变量。

## 安全与失败行为

- HTTP 非 200、JSON 结构错误、缺页、空页、记录数不一致、重复代码或必要字段缺失，均抛出 `DataSourceError`。
- 任一页失败即整次检查失败，不返回部分市场结果，不发送 Server酱通知。
- 完整性以接口声明总数、实际唯一代码数和连续页集合一致为准。
- 不记录代理地址、SendKey 或其他凭据。

## 测试与验收

- 单元测试使用本地 JSON fixture，覆盖多页合并、必要字段映射、缺页、重复代码、HTTP 错误和总数不一致。
- 现有 13 项 AkShare 合并和 watch-only 提醒测试必须继续通过。
- 交易时段无推送运行必须返回非空全市场结果，Top N 含价格、最新官方净值、净值日期和 `premium_basis=latest_official_nav`。
- 真实验证通过后删除 Palmmicro 行情 provider/model；旧 Eastmoney 申赎 provider 也在新合并链路验证通过后删除。

## 明确不做

不加入缓存、数据库、看板、自动重试、备用数据源、实时净值估算、历史误差统计或交易执行判断。
