# “LOF提醒”手动快捷方式设计

## 目标

在 Windows 桌面创建名为“LOF提醒”的快捷方式。用户双击后，无论是否处于交易时段，都向 GitHub Actions 提交一次前 15 只 LOF 的更新请求；自动计划任务的工作日 13:00–14:50 限制保持不变。

## 方案

复用现有 `tools/trigger_daily_check.py`，为它增加显式的 `--force` 手动模式：

- 无参数运行：供 Windows 任务计划程序使用，继续执行工作日和时间窗口检查。
- `--force`：供桌面快捷方式使用，跳过时间窗口检查，但仍复用同一条 `gh workflow run` 命令。

项目内增加一个最小 Windows 启动脚本。桌面快捷方式“LOF提醒”只负责启动该脚本，不包含 GitHub 凭据、Server酱 SendKey 或采集逻辑。

## 用户流程

1. 用户双击桌面的“LOF提醒”。
2. 启动脚本调用固定的 Python 解释器，并执行现有触发器的 `--force` 模式。
3. GitHub CLI 向 `hkt321/arbitrage-alert` 的 `daily-check.yml` 提交 `top=15` 的 `workflow_dispatch`。
4. 窗口显示“请求已提交，微信稍后更新”或明确的失败信息，并在 5 秒后关闭。

“请求已提交”仅表示 GitHub 接受了运行请求，不表示远端采集和微信推送已经完成。

## 失败处理

- 找不到 Python、GitHub CLI 未登录、网络不可用或 GitHub 拒绝请求时，返回非零退出码并在窗口显示失败。
- 手动模式不因周末、收盘后或不在自动窗口而跳过。
- 不在本地保存或复制任何密钥。

## 验证

- 单元测试证明自动模式在窗口外仍跳过。
- 单元测试证明 `--force` 在窗口外和周末仍只提交一次相同工作流。
- 检查启动脚本只调用 `--force`，且未包含凭据。
- 检查桌面快捷方式名称、目标、工作目录和图标可解析。
- 实际点击验收只执行一次；确认 GitHub 产生一个 `workflow_dispatch` 运行，并最终收到一次微信提醒。

## 范围外

- 不新增 GUI、日志数据库或本地采集链路。
- 不等待 GitHub Actions 完成后再关闭窗口。
- 不修改自动任务的触发时间、任务名称或运行条件。
