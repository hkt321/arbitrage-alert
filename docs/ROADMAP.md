# 开发路线

## M0：项目拆解

- 明确 MVP 边界。
- 建项目目录和文档。
- 做静态看板原型。

## M1：前端 MVP

- 完成基金列表看板。
- 完成分类、自选、排序、搜索。
- 完成阈值设置和机会高亮。
- 完成模拟提醒记录。

## M2：数据接入

- 调研并选定第一个真实行情数据源。
- 建立重点基金档案，包含跟踪指数、估值模型、净值披露滞后、申购路径。
- 建行情采集脚本。
- 实现实时估值引擎。
- 实现估值误差回放和校准。
- 统一清洗为内部数据模型。
- 采集申购限额、申赎状态、交易状态、费用、确认/到账周期。
- ETF 额外采集申购赎回清单和 IOPV 相关字段。
- 前端从 API 获取数据。

建议路径：

```text
当前：TdxQuant 实时行情 + 官方公告/PCF 补充申赎字段
备选：公开行情源 + 官方公告/PCF 补充字段
后续：如能开通 QMT，再增加 QMT 行情适配器
原型：公开行情源 + 官方公告/PCF 补充字段
```

## M3：提醒系统

- 增加规则配置。
- 增加通知渠道：企业微信 / Telegram / 邮件。
- 增加提醒去重和冷却时间。

## M4：部署

- 本地常驻运行。
- 云服务器部署。
- 日志、失败重试、数据源异常告警。

## M5：交易辅助

- 只展示交易建议字段，不自动下单。
- 如需自动交易，单独设计权限、风控、撤单和异常处理。
